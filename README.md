# Paradata Feature Extraction Pipeline

A research-grade Python project for engineering timing-based features from mobile survey paradata. 

This project analyzes timing data collected from SurveyCTO and ODK surveys and extracts features that can be used to predict survey data quality issues.

## Project Structure

- `data/`: Directory for raw and processed paradata logs (e.g., CSV audit logs).
- `notebooks/`: Jupyter notebooks for reproducible analysis and exploration.
- `src/`: Core Python library for feature extraction
  - `parsers/`: Parsers for SurveyCTO and ODK audit logs.
  - `features/`: Modules for calculating response time, pause, navigation, and rhythm features.
  - `validation/`: Statistical tests to validate feature discriminative power.
  - `visualization/`: Tools for plotting timing distributions.
- `tests/`: Automated tests (`pytest` and `hypothesis`).

## How It Works

This project is a data engineering pipeline designed specifically to catch "bad actors" or anomalies in mobile survey data collection (like when an enumerator speed-runs a 30-minute survey in 2 minutes, or takes suspicious 15-minute breaks during an interview).

It takes the raw timing logs (paradata/audit files) generated by survey platforms like **SurveyCTO** or **ODK**, where every single button press, question appearance, and swipe is recorded, and mathematically transforms those millions of rows into a clean, single-row summary per interview containing predictive features.

### 1. The Input (Raw Paradata)
You start by placing your raw `.csv` audit logs from SurveyCTO or ODK into the `data/` folder. 
These files typically contain a messy, chronological log of events:
- `interview_id`
- `question_id` (the node or screen name)
- `start_time` and `end_time`
- `event_type` (e.g., Question answered, backward swipe, resume, pause)

### 2. The Processing Pipeline
You run the automated pipeline from your terminal:
```bash
python run_pipeline.py --data-dir data --output-dir output --parser surveycto
```
Behind the scenes, the pipeline:
1. Groups the millions of log lines by `interview_id`.
2. Extracts **Response Times** (mean, median, variance).
3. Detects **Pauses** (gaps in time between questions that exceed normal thresholds).
4. Analyzes **Navigation** (counting how many times they hit the "Back" button, or how many questions they rapidly "straightlined" past in under 2 seconds).
5. Calculates **Rhythm** (how erratic their answering speed was) and a **Speed Index** (comparing their total duration to the global median of all interviews).

### 3. The Output
The pipeline outputs a single, clean file: `output/features_output.csv`. 
In this file, every interview is compacted into a single row containing numbers (the features). Notable features include:

- **Speed Index:** How fast the interview was relative to the global survey median.
- **entropy_response_time:** We calculate Shannon Entropy ($H(X) = - \sum p(x) \log p(x)$) on the distribution of a respondent's answer times. A low entropy indicates mechanical, rapid-fire, highly uniform answering (a strong indicator of fake data). High entropy indicates natural human variation.
- **is_anomalous:** A binary flag (0 or 1) indicating if the interview is a severe statistical outlier. Because survey timing data is heavily skewed (non-normal), we use **Robust IQR (Interquartile Range)** bounds rather than naive Z-scores. An interview is flagged if its total duration falls outside $Q1 - 3*IQR$ or $Q3 + 3*IQR$.

### 4. Analysis & Jupyter Notebooks
Once you have `features_output.csv`, you use the **Jupyter Notebooks** in the `notebooks/` folder.
The notebooks are where the actual research and data science happen. Instead of terminal commands, notebooks give you an interactive, visual environment where you can:
- Import your `features_output.csv`.
- Run statistical tests (from `src.validation`) to see if the fast response times correlate with poor data quality.
- Generate charts and graphs (from `src.visualization`) to visually prove your findings for academic publication.
